# ADR 0001. 도메인 단위 폴더 구조(DDD-lite) 채택

- 날짜: 2026-08-26
- 상태: 채택

## 배경
소규모(1인) 프로젝트지만, 작업물·댓글·관리자·지도가 서로 얽히기 쉽다. 문서와 코드가 같은 단위로 나뉘어 있어야 AI 에이전트/사람이 한 도메인만 읽고 작업할 수 있다.

## 결정
- `docs/domain/{domain}/` (overview, db, prd) 와 `lib/domain/{domain}/` 을 1:1 로 맞춘다.
- 애그리거트·불변식·유스케이스는 overview.md에 먼저 쓰고 코드로 옮긴다.
- 헥사고날까지 가지 않는다: 리포지토리 인터페이스·DI 컨테이너 없이 Supabase 호출을 `queries/actions`에 직접 둔다. 외부 API(Kakao)만 포트/어댑터로 분리.

## 대안
- 기능(feature) 폴더: 화면 단위라 도메인 규칙이 흩어짐.
- 완전한 헥사고날/클린 아키텍처: 이 규모에선 과함.

## 결과
- 도메인 간 결합은 `types.ts` 공개 함수로만 허용 (10-conventions.md).
- 규모가 커져 리포지토리 추상화가 필요해지면 도메인 단위로 점진 도입.
