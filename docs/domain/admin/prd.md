# admin — PRD

## 1. 목표
사장님이 폰에서도 쉽게 로그인해서 작업물·카테고리·댓글을 관리한다. 인증 자체는 최대한 단순하게.

## 2. 유저 스토리
- US-A1. 사장님으로서 이메일/비밀번호로 로그인하고, 다음에 다시 열면 로그인이 유지되길 원한다.
- US-A2. 사장님으로서 로그인 후 바로 "작업물 등록" 버튼이 보이길 원한다.
- US-A3. 개발자로서 관리자 페이지가 검색엔진에 노출되지 않길 원한다.

## 3. 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| A-1 | `/admin/login`: 이메일, 비밀번호, 로그인 버튼. 실패 시 "이메일 또는 비밀번호를 확인해 주세요" | 필수 |
| A-2 | 세션 유지 (쿠키, 기본 1주) | 필수 |
| A-3 | `/admin/**` 미들웨어 가드: 미인증 → 로그인, 인증됐지만 admins 아님 → "권한이 없어요" 페이지 | 필수 |
| A-4 | 관리자 레이아웃: 상단 탭 (작업물 / 카테고리 / 댓글), 로그아웃 | 필수 |
| A-5 | `/admin` 기본 화면 = 작업물 목록 + 큰 "새 작업물" 버튼 | 필수 |
| A-6 | 모든 관리자 페이지 `noindex, nofollow` + robots disallow | 필수 |
| A-7 | 비밀번호 재설정 (Supabase 이메일) | 권장 |
| A-8 | 이메일 OTP 로그인 | 선택 (v2) |

## 4. 수용 기준
- [ ] 로그아웃 상태에서 `/admin/works/new` 접근 → `/admin/login?next=/admin/works/new`로 이동, 로그인 후 원래 페이지로 복귀.
- [ ] admins에 없는 사용자로 로그인 → 관리 화면 접근 불가, RLS로 DB 쓰기도 거부.
- [ ] `curl -I /admin` 응답에 `X-Robots-Tag: noindex`.

## 5. 비범위
- 역할/권한 세분화
- 다중 업체(테넌트)
